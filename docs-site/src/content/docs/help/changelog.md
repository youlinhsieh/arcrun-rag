## 1.4.42（2026-08-12）

建議更新——這一版在修**更新這件事本身**。

- 🏷️ **更新完之後，設定頁還看得到版本號**：
  以前用指令更新完，設定頁的「版本」會變成「無法讀取目前版本」——
  因為重新部署會把版本標籤連同你的其他設定一起洗掉。
  現在**版本標籤每次更新都重新烙上，你自己調過的設定則原封保留**。
  - 這件事比看起來重要：版本號是你判斷「我到底更新到了沒」的唯一依據，
    而小幫手也靠它判斷雲端是不是太舊。它消失時，小幫手會一直以為你需要更新。

- 🗄️ **更新不會再報「部署物缺某某檔案」**：
  有兩個資料庫升級檔**從來沒被打包進來過**——它們被一條「不要收資料庫備份」的規則
  誤判成備份擋掉了。於是每個人更新到最後都會看到兩行紅字。
  現在它們正常隨版本出貨，更新可以乾淨跑完。

- 🔒 **順帶把 credential 目錄搬到正規位置**：
  上面那兩個升級檔做的事——把「你有哪些金鑰」這份目錄從一張多餘的表搬進標準結構。
  **你的金鑰本身不在那張表裡**（它們在 Cloudflare 的保險箱），所以這次搬移不會動到任何金鑰。

## 1.4.41（2026-08-12）

建議更新——這一版在修**你的 AI 助理用什麼身分看你的資料**。

- 🔐 **AI 助理現在用「你」的身分查東西**：
  你把 MCP 掛上去的時候輸入過帳號密碼，那跟你登入 Portal 是同一件事——
  **那個動作本身就是授權**。但以前系統沒有把你的身分接住，它驗完只記得「密碼對不對」，
  轉頭改用一把系統內部的鑰匙去查資料。那把鑰匙在部分實例上根本沒配對成功，
  於是助理問什麼都回「未授權」。
  現在它帶著你的登入身分去查，**你看得到的它就看得到，你看不到的它也看不到**。
  - ⚠️ **更新後要重新連一次 MCP**：舊的連線沒有身分資訊，系統會直接請你重連，
    而不是偷偷退回舊的那條路。

- 🛡️ **別人不能靠編號讀到你的東西**：
  以前只要知道一筆資料的編號就讀得到它，系統不會檢查那筆是不是你的；
  而助理走的那條路也繞過了「你有權限看哪些庫」的過濾。
  現在**不是你的資料，跟不存在一樣回「查無此筆」**——不會因為錯誤訊息不同而洩漏它存在。

## 1.4.40（2026-08-12）

建議更新——這一版在修**它動到你自己的檔案**這件事。

- 📓 **它不會再蓋掉你 Logseq 裡同名的頁面**：
  以前小幫手把整理出來的卡片寫回你的筆記庫時，用的是**跟你的檔案一樣的命名方式**
  （例如 `2026_08_12.md`），於是你打開 Logseq 會看到自己的日誌被一份機器寫的內容取代。
  現在機器寫進去的每個檔案都帶 `arcrun-` 前綴，不可能再跟你的頁面撞名。
  - 已經被弄亂的舊檔案，用 `collector tidy` 收拾。**它預設只列給你看、什麼都不動**，
    確認清單沒問題後再加 `--apply`。
  - ⚠️ 這個指令**從不刪除任何東西**：只有改名與搬移。覺得搬錯了，自己搬回去就是。
    舊版小幫手鋪進去的開發用檔案會被移到 `.arcrun-rag/legacy-template/`，內容原封不動。

- 🔑 **裝完不會再叫你去 Google 申請 AI 金鑰**：
  那一步早就不需要了（金鑰改由系統這邊供應），但安裝完成清單還留著，
  等於叫每個新用戶去做一件白工。現在清單只剩「下載小幫手」一項。

- ⏱️ **工作流裡的「等一下」不再燒運算額度**：
  以前只要流程裡有等待節點，不管設定等三秒還是三十秒，都會一路撐到運算上限被系統砍掉。
  原因是等待被放在沙箱裡執行，而那個沙箱**沒有「睡覺」這個能力**，只能空轉。
  現在等待改由引擎本身處理——等三十秒和等三秒一樣不花錢。

## 1.4.38（2026-08-12）

建議更新——這一版主要在修**搜尋**。如果你曾經覺得「東西明明在庫裡，就是搜不到」，就是這個。

- 🔍 **用一句話問，終於找得到了**：
  以前搜尋是拿你打的**整串字**去比對，所以只要那幾個字在文件裡沒有剛好連在一起，
  就會回你 0 筆——而你手上的東西其實在庫裡。
  舉個真的發生過的例子：查「Gemini 逃生口」回 0 筆，但單獨查「Gemini」有八百多行。
  現在會把你打的話拆成詞分別找，再照「命中幾個詞」排序。
  ⇒ 實測（一萬八千筆真實文件、三百題）：以前只有 11 題找得回正確那一筆，
  現在 280 題把它排進前十名、209 題排第一。單獨查一個詞的結果**逐字不變**。
- 📚 **「藏書地圖」不再每看一次就偷偷寫一批紀錄**：
  以前每打開一次總覽頁，它都會判定「資料過期」而重算一次並留下一筆新紀錄
  ——那在無聲吃掉你每天的資料庫寫入額度。現在只有資料真的變了才重算。
- ⏳ **補算語意索引改成「從最新的開始、每天有上限」**：
  以前它從最舊的資料開始補，而且沒有煞車——你今天寫的東西要排到最後，
  額度還可能一次被燒光（那份額度是跟「整理筆記」共用的）。
  現在先補新的，每天用到設定的上限就停手。
- 🧩 **AI 不會再被告知「這個零件不存在」**：
  有一批零件是系統自帶的，但清單查不到它們，於是 AI 會以為缺零件而改用別的做法
  ——即使那顆零件在同一台機器上明明跑得動。現在查得到了。

## 1.4.33（2026-08-10）

建議更新——這版修的是「**改完密碼，就被自己的系統踢出去**」。

- 🔑 **改完密碼不會再被登出**：
  以前按下「更新密碼」之後，畫面會把你踢回登入頁；而這時候瀏覽器記住的還是**舊密碼**，
  你照著填就一直「email 或密碼錯誤」，試幾次還會被鎖 15 分鐘——**看起來就像系統把你關在門外**。
  原因是密碼存好之後，Cloudflare 要花幾十秒把新設定鋪到各地，
  這段期間系統會誤判成「查無此人」，然後把你的登入狀態直接刪掉，**鋪好了也回不來**。
  現在這段期間會誠實告訴你「正在更新中，你並沒有被登出」，並且**永遠不會**因為一時讀不到就刪掉你的登入狀態。
- 🔗 **忘記密碼可以自己救回來了**：
  在登入頁按「忘記密碼」，會收到一條「修改密碼」連結；點進去**不必輸入現在的密碼**，
  直接設新的就好。連結只能用一次、30 分鐘後失效。
  （這條路要能寄信才會通，見下方「還沒到你手上的」。）
- 🧩 **改密碼與忘記密碼變成同一個機制**：
  同一個畫面、同一條寫入路徑，差別只有「要不要輸入現在的密碼」。
  以前是兩套各自實作，而兩套都會壞。
- 🔌 **新安裝的實例終於真的有 MCP**：
  以前安裝器不會裝 `arcrun-mcp`，所以照說明去 claude.ai 加連線會失敗。現在它在安裝清單裡了。
- 🩺 **一條指令就看得出這台的 MCP 是哪一版**：`/health` 會回報版本與認證方式。

**還沒到你手上的**：忘記密碼的**寄信**那一段還沒開啟——按下去目前會誠實回報「尚未設定寄信」，
不會假裝已經寄出。等寄信服務上線後會再發一版。

## 1.4.30（2026-08-10）

建議更新——這版修的是「**搬了資料就登不進去**」。

- 🔑 **換掉或搬動知識資料庫之後，你還是登得進去**：
  以前登入帳號跟知識資料存在同一個地方，所以只要換了資料庫、或系統換了一組內部代號，
  等於連鑰匙一起換掉——畫面只會跟你說「email 或密碼錯誤」，讓你以為是自己記錯密碼。
  現在登入資料有自己的家，搬資料不會動到它。
- 🚪 **登不進去時會告訴你到底發生什麼事**：
  如果這台實例根本沒有任何登入資料（不是密碼錯），畫面會直接說出來並告訴你怎麼救，
  而且這種情況**不會**把你算進「密碼錯太多次」的鎖定。
- ⏱️ **剛建好帳號就登入，不會再被自己鎖在門外**：
  以前設定完帳號馬上登入會連續失敗幾次、然後被鎖 15 分鐘。現在第一次就進得去。
- 📝 **安裝時如果這個帳號早就存在，會說實話**：
  以前你在安裝畫面填的新密碼會被安靜丟掉，實際生效的還是原本那組，而畫面不會提。
  現在會明白告訴你「你剛才輸入的密碼沒有被採用，目前的密碼仍是當初那一組」。
